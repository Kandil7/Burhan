# Database Migrations

The Burhan PostgreSQL schema is managed by the **raw SQL files in this directory**.
Alembic is scaffolded (`alembic/`, `alembic.ini`) but has no revisions, so
`alembic upgrade head` is currently a no-op. Do not rely on Alembic to create the schema.

## Files

| File | Purpose |
|------|---------|
| `001_initial_schema.sql` | Full initial schema: Quran tables (`surahs`, `ayahs`, ...), `translations`, `tafsirs`, and other core tables. |
| `versions/002_quran_translations_tafsir.sql` | Delta: full-text search GIN indexes for `tafsirs.text` and `translations.text`. |
| `versions/003_align_unique_constraint_names.sql` | Delta: renames the database-generated UNIQUE constraints on `ayahs`, `translations`, and `tafsirs` to the names the SQLAlchemy models declare. |

Every file is idempotent (`CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`,
guarded `DO` blocks), so they are safe to re-run.

## Applying Migrations

In order:

```bash
docker exec -i Burhan-postgres psql -U Burhan -d Burhan_db < migrations/001_initial_schema.sql
docker exec -i Burhan-postgres psql -U Burhan -d Burhan_db < migrations/versions/002_quran_translations_tafsir.sql
docker exec -i Burhan-postgres psql -U Burhan -d Burhan_db < migrations/versions/003_align_unique_constraint_names.sql
```

Or use the CLI, which applies every file in order:

```bash
python scripts/cli.py db migrate
```

`scripts/ingestion/ingest_and_run.py` also applies every `migrations/*.sql` followed by
every `migrations/versions/*.sql`, in sorted order.

## Adding a Migration

1. Create a new numbered SQL file, for example `migrations/versions/003_<slug>.sql`.
2. Keep it idempotent (`IF NOT EXISTS`) so re-runs do not fail.
3. Add it to the list in `scripts/cli.py` (`cmd_db_migrate`); the ingestion runner picks
   up `versions/*.sql` automatically.
4. Record the change in the schema docs.

## Relationship to Alembic

`alembic/env.py` points `target_metadata` at `src/data/models.Base.metadata`, so a
baseline revision can be autogenerated once a live database is available:

```bash
alembic revision --autogenerate -m "baseline"
alembic stamp head  # for databases already created by the SQL files
```

Until that happens, treat the SQL files as the source of truth.
